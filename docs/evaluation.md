# Experimental methodology and interpretation

Experiments consume deterministic workload payloads generated by Mersenne Twister with recorded seeds. The *real* verifier never receives attack labels; these are retained by the measurement driver only. `results/raw/` files contain observations from execution, with a backend column.

E1: AT1, AT6, AT8 and late-after-revocation AT7; E2: AT2, AT3, AT4, AT10; E3: per-event anchor call counts and real build/verification time; E4: physically paced batch-size/rate tests with genuine monotonic event-to-anchor delay (the memory backend is still not Ethereum); E5: pre/post revocation and valid rotated epoch; E6: internally consistent fake AT9 events with stolen key and genuine signed clock-skew AT5; E7: process timing and RSS stability.

One run is the independent experimental unit. Statistics include exact Clopper-Pearson binomial confidence bounds, paired McNemar tests using shared trial index, Holm adjusted p-values, bootstrap median intervals and coefficient of variation. Do not treat multiple events within a run as independent samples.

In-memory measurements establish Python protocol behavior, not blockchain costs. EVM measurements require live Anvil and must be evaluated in multiple independently reset local chain sessions under controlled CPU/power conditions. If a separate session cannot be reset fairly, record that as a confounder. E3's 10,000 per-event B1 cap is transparent; extrapolations beyond executed transaction counts are not reported as observations.

### Required external validation before publication

- Compile and execute Foundry tests with a pinned compiler release.
- Run actual EVM ledger experiments, verify the receipts and archived contract bytecode/ABI.
- Freeze configuration grids with attack rates, stream volumes, batch sizes and order randomization; perform the full replicated study, not only this smoke/pilot runner.
- Independently audit crypto design, contract, key lifecycle, storage rollback, and canonicalization interoperability.
- Compare against validated contemporary secure-logging systems, not only internal ablations.
- Review benchmark stability and contradictory/negative results, with machine-specific environment manifests.
