# Reproducible E1–E12 analysis

- **E1/E2**: deterministic verification classifications on labeled naive/adaptive artifacts. No binomial confidence intervals or statistical p-values for deterministic classifications. Adaptive AT8 modifies a real event and recomputes public commitments; a strong unsigned attacker may accept it, while the anchored signed path must reject it. E2 adds unsigned history reissuance (counts, sequence numbers, leaf hashes and batch manifests recomputed).
- **E3/E4**: FI is included alongside static P1. Construction, anchoring and verification are measured separately. A reset Anvil state is used when the external chain is configured. Physical pacing in the full E4 grid takes substantial wall-clock time; a configured full run is not evidence that the full run has been executed.
- **E5/E6**: revocation and fabricated future records still matter. The FI ratchet cannot stop a current-key holder from deriving future signing keys. It is not a source-truth protocol.
- **E7**: measures in separately spawned worker processes; `ru_maxrss` reflects each child's peak, not per-algorithm instant usage.
- **E8**: CT signed checkpoints, inclusion/consistency checks, an on-contract anchored-root reference, and the same AT1–AT4 archive mutations. Report each trust model explicitly. The anchored CT adapter commits a CT checkpoint root to the same contract but does not imply that the CT application speaks the PABLA protocol. Computation is in Python reference code, not optimized CT production code.
- **E9**: compromised current key against a *previously signed pending period*, already anchored history, and future fabrication. FI vs FI-noerase/P1/B4 provides the relevant differential. CT anchored/offchain and a missing-transition keychain reference are separate rows, not a single matched EVM gas comparison.
- **E10**: 10/100/1000/10000 nominal-rate seeded synthetic timing and event-exposure model; models and counted observations are not Ethereum confirmation times.
- **E11**: selected deadline/batch-size windows are processed through the collector and the configured ledger. Gas is filled **only** from actual Anvil receipts; memory rows contain transaction-call costs only. A greedy deadline policy is not evidence of global minimum gas expenditure.
- **E12**: LANL event timestamps and source-line sizes can be streamed from a separately downloaded LANL corpus. The loader checks relative timestamp order, records a SHA-256 checksum of the *entire original file* and models anchor deadlines. If the path is absent the experiment is explicitly skipped. Example rows in LANL's documentation are not substituted for a full data set.

## Run profiles and provenance

`python Main.py` is a small non-chain pilot with distinct `output/testN` directories. To run against a **real local Anvil node**, install Foundry and web3 extras, deploy the pinned contract, and use `--backend anvil --require-chain` after confirming the correct contract ABI. The `--profile full` grid may take many hours or days because 10,000 events at 10 events/s require 1,000 seconds for just one paced condition, before other rates, baselines, and 30 repetitions. Archive all `results/raw` files and chain receipt hashes; do not extrapolate measured gas from in-memory calls.

E12 data source: Los Alamos National Laboratory, [Comprehensive, Multi-Source Cyber-Security Events](https://csr.lanl.gov/data/cyber1/), A. D. Kent (2015), DOI 10.17021/1179829. The data is publicly released, but its official acquisition path asks for the intended use; no dataset is bundled. Publication-level performance and novelty claims require independent comprehensive runs and a related-work review.
